# 影之幻境 · 统计上报与聚合设计（v1 草案）

> 状态：设计稿，**服务器尚未部署**。本文件只定义契约与口径，代码先做本地部分。
> 最后更新：2026-10-19。

## 1. 要做的三件事

| 功能 | 数据来源 | 是否需要服务器 |
|---|---|---|
| 某张牌的**出现率** | 游戏卡池权重（待从热更程序集挖）+ 本地商店读取 | 不需要（本地算） |
| 某张牌的**抓取率**（出现后被拿走） | 玩家自己商店的"出了/拿了"事件 | 需要（聚合） |
| 某套**最终阵容的胜率/吃鸡率** | 每局结束上报：最终阵容 + 名次 | 需要（聚合） |
| **阵容教程** | 静态内容 + 服务端更新 | 可选 |

原则沿用 §1：**宁可不给数，也不给错数**。样本不足就显示"样本不足"，不做外推。

## 2. 数据流

```
客户端（只读内存）
  ├─ 每局结束：最终阵容 + 名次 ──┐
  ├─ 每回合商店（可选）：出了什么/拿了什么 ─┤
  │                                      ▼
  │                              上报（默认关，开了才传）
  │                                      ▼
  │                            服务器：去重 → 按版本/段位分桶聚合
  │                                      ▼
  └────────────── 下发 meta 快照（带样本量/版本/更新时间）◄──┘
```

- 客户端**永不**上报对手信息、账号、昵称。
- 服务器**永不**下发"对手阵容/对手下回合"这类信息。

## 3. 上报契约 v1（一局一条）

```json
{
  "v": 1,
  "game_id": "随机 UUID（本地生成，用于服务器去重）",
  "ver": "11.9.10",
  "mode": "ranked",
  "tier": 15,
  "hero": 1101,
  "rank": 1,
  "turn": 14,
  "final_board": [
    {"card_id": 10501110, "star": 2, "evolved": true},
    {"card_id": 10501111, "star": 1, "evolved": false}
  ],
  "played_at": "2026-10-19T14:30:00+08:00"
}
```

字段说明：
- `ver`：**卡库版本**（`knowledge/meta.json` 的 `sourceVersion`）。版本不同的数据不混算。
- `tier`：段位/幻境等级分桶。未知填 `null`，聚合时单独放"未知"桶，不参与主榜。
- `rank`：1..8，来自结算名次表（§6-2 的口径不变：出局后才采信）。
- `final_board`：**最后一回合开战时的我方阵容**（不是死后的空场）。只存 `card_id/star/evolved`，
  不存攻血（攻血受光环影响，会污染"阵容"这个概念）。
- `game_id` 由客户端生成并持久化，服务器按它去重（防重传）。

商店事件（可选，第二阶段）：
```json
{"v":1,"shop":true,"turn":5,"offered":[[10501110,2],[10401120,1]],"picked":[10501110],"tier":6}
```
- 只在"商店刷新"时上报；`picked` 可以是空数组（没买）。

## 4. 阵容签名（本地与服务器共用）

- 规范化：每张卡取 `(card_id, star, evolved)`，按 `card_id` 升序、`star` 升序排序，拼成
  `10501110:2:e|10501111:1:x`。
- **主 key 用"忽略 star/evolved 的 card_id 多重集"**（`10501110|10501110|10501111`）：
  星级/进化属于强度差异，不是"阵容"本身；太细会导致每套阵容只有 1 个样本。
- 展示时按 star 降序输出卡名，星级用 `★★★` 标注。

## 5. 聚合口径

### 5.1 阵容维度（以主 key 分组）

| 指标 | 定义 |
|---|---|
| `samples` | 该阵容的整局样本数 |
| `firsts` | 名次 == 1 的局数 |
| `first_rate` | `firsts / samples`（**这就是"最终阵容获得第一的比例"**） |
| `top4_rate` | 名次 <= 4 的比例 |
| `avg_rank` | 平均名次（越低越好） |

- 分桶：`ver` + `tier`。样本 < **30** 不展示（显示"样本不足"）。
- 榜单排序：`first_rate` 降序，样本 >= 30 才进榜；同时显示样本量（避免 1/1 = 100%）。

### 5.2 卡牌维度

| 指标 | 定义 |
|---|---|
| `appearances` | 这张牌出现在多少次"最终阵容"里 |
| `in_first` | 其中名次 == 1 的次数 |
| `champion_rate` | `in_first / appearances`（冠军阵容里的出现占比） |
| `pick_rate` | 需要商店事件（第二阶段） |

> 注意区分：`champion_rate` 高 ≠ 这张牌强（可能只是热门阵容里的常客）；要同时看 `samples`。

## 6. 展示

- 控制台新增「统计」页：热门最终阵容榜（吃鸡率/前四率/平均名次/样本量）、单卡冠军占比。
- 悬浮球：**本局**的最终阵容要到结算才有，所以只在对局结束后显示「本阵容：样本 N，吃鸡 X%」。
- 数据版本过期（`ver` 与当前卡库不一致）→ 整页标注「数据版本过旧」，不静默使用。

## 7. 隐私、开关、断网

- 默认**关闭**上报；设置里打开后生效，`device` 为本地随机 UUID，可在设置里重置。
- 上报失败进 `logs/upload_queue.jsonl`（上限 500 条，先进先出），下次启动补传一次。
- 下发快照缓存到 `logs/meta_cache.json`；断网/失败时用缓存，没有缓存就显示"暂无数据"。

## 8. 本地文件

| 文件 | 作用 |
|---|---|
| `logs/final_boards.jsonl` | 每局最终阵容（本地，未上报也留着） |
| `logs/upload_queue.jsonl` | 待上报队列 |
| `logs/meta_cache.json` | 服务器下发快照 |

## 9. 待定 / 风险

1. **服务器形态未定**：地址、鉴权、存储都空着；先按"上报 JSONL + 下发 JSON"对接。
2. **样本偏差**：只有装插件的人上报，且偏功利。榜单要标样本来源。
3. **版本漂移**：`ver` 不一致的数据不混算。
4. **合规**：只统计"自己这局"；触碰对手信息的字段一律不采集。
5. **最终阵容的采集点**：必须在"最后一场开战瞬间"记录（出局时场上已空），见 §10。

## 10. 采集改动清单（watch_mem.py）

1. `board_of()` 增加 `card_id` / `evolved` 字段（只增不减，旧数据仍可读）。
2. 新增 `_LAST_BOARD`：每场开战读到 `battle["player"]["board"]` 时保存一份。
3. 出局记录时优先用 `_LAST_BOARD` 作为 `final_board`（回退：当场 board）。
4. `history.finish_game()` 的 `board` 字段存这份 `final_board`（已支持）。
